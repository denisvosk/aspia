# Обновления Aspia 2.7 → 2.7.1 через свой Caddy

Подготовленный комплект; на рабочем сервере ничего автоматически не меняет.
Сборка Windows #17 прошла для x86 и x64, включая протокольные/OLE-тесты,
проверку содержимого MSI и обновление установленного Host 2.7.0 до 2.7.1
с сохранением тестовой конфигурации и запуском службы.
Реальное копирование через Проводник между двумя компьютерами и обновление
через публичный HTTPS-сервер ещё требуют проверки.

Черновик с шестью MSI и исходниками (открывать под своим аккаунтом GitHub):
https://github.com/denisvosk/aspia/releases/tag/untagged-c4751170e8f914a9fab2

## Проверить сейчас, не дожидаясь автообновления

На первом компьютере нужен запасной способ входа либо человек рядом.
Скачайте на него Host MSI **той же разрядности, что установленный Host**.
Разрядность Windows сама по себе недостаточна: на 64-битной Windows может
стоять 32-битный Host. Путь службы можно посмотреть из PowerShell:

```powershell
Get-CimInstance Win32_Service -Filter "Name='aspia-host-service'" | Select-Object PathName
```

Стандартный путь `Program Files (x86)\Aspia\Host` указывает на x86,
`Program Files\Aspia\Host` на 64-битной Windows — на x64.
При нестандартной установке проверьте установленный пакет отдельно.
Проверьте SHA256 скачанного MSI по `SHA256SUMS-x86.txt` или `SHA256SUMS-x86_64.txt`
из того же черновика. Сохраните копию `C:\ProgramData\aspia\host.json` в закрытой
папке, не на сайте. Не удаляйте старый Host перед установкой нового.

Для x64 поместите MSI в `C:\Temp`. Откройте **cmd от администратора** и выполните:

```bat
msiexec.exe /i "C:\Temp\aspia-host-2.7.1-x86_64.msi" /qn /norestart /L*v "C:\Temp\aspia-host-upgrade.log"
```

Для x86 замените имя на `aspia-host-2.7.1-x86.msi`.
Повышение прав происходит до начала установки. `/qn` убирает окна и запросы,
`/norestart` запрещает автоматическую перезагрузку Windows. При замене службы
связь Aspia оборвётся; установку продолжает Windows Installer. Через минуту-другую
попробуйте подключиться заново. После восстановления проверьте версию и службу.
Если связи нет — используйте запасной доступ и журнал; не запускайте установщик
повторно вслепую. Тихая установка не гарантирует успешного завершения на любой машине.

Для проверки буфера установите новую Console или Client на управляющий компьютер
и новый Host на тестовый удалённый. Router/Relay 2.7 менять не требуется.
Проверьте оба направления: обычный файл, папку, кириллическое имя, пустой файл,
большой файл; сравните SHA256. Старая Console/Client не получит новую функцию сама.

## Когда обновляет встроенный механизм

В `source/host/server.cc` таймер запускается каждые **5 минут**. Он сравнивает
текущее время с `LastUpdateCheck`. При частоте `"1"` запрос делается, когда прошло
не меньше 24 часов. Это не «в полночь» и не фиксированный час. Если компьютер
выключен, проверка будет после запуска службы, при очередном срабатывании таймера.
Найденная более новая версия загружается и запускается через `msiexec /i ... /qn`.
Отдельного ожидания простоя пользователя нет. Штатный путь не добавляет `/norestart`.
Публикация XML может вызвать обновление работающих компьютеров при следующей проверке.

Кнопка «Проверить обновления» использует другой путь (`common/ui/update_dialog.cc`):
подтверждение установки, загрузка, повышение прав при необходимости, затем
`/qb-!` — базовое окно прогресса. Для первого удалённого теста команда выше
предсказуемее: все права получены заранее и перезагрузка явно запрещена.

## Что делает SeedKey

Это не подпись/контрольная сумма JSON и не шифрование всей конфигурации.
`base/peer/server_authenticator.cc` использует его для формирования SRP-ответа
на неизвестную/отключённую учётную запись. Для действующего пользователя используются
его Salt и Verifier. В `host/ui/config_dialog.cc` при сохранении создаётся новый
UserList без старого seed; `SystemSettings::setUserList` генерирует новый SeedKey.
Поэтому он меняется даже при изменении только галочки в интерфейсе.
При нашей правке он остаётся прежним; Users и ключ роутера тоже не меняются.

## Подготовить сервер, пока без выдачи обновления

1. Содержимое папки `server` скопируйте в `C:\Web\Aspia\updates`.
   Создайте там подпапку `files`. XML сейчас содержат `<no-update/>`.
2. Из черновика скопируйте оба Host MSI в `C:\Web\Aspia\updates\files`.
   Там же можно разместить исходный ZIP и LICENSE.md из этой сборки.
   Не кладите сюда host.json, его резервные копии и любые секреты.
3. В **существующий** блок `https://192.0.2.1 { ... }` активного файла
   `C:\chat_ZPP_bot\Caddyfile` добавьте содержимое `Caddy-updates.fragment`.
   Оставьте прежние TLS, root, file_server и весь блок бота как есть.
   Перед редактированием сохраните копию Caddyfile.
4. Проверьте и перезагрузите конфигурацию уже работающего Caddy:

```powershell
& "C:\chat_ZPP_bot\caddy.exe" validate --config "C:\chat_ZPP_bot\Caddyfile" --adapter caddyfile
# Только если выше Valid configuration:
& "C:\chat_ZPP_bot\caddy.exe" reload --config "C:\chat_ZPP_bot\Caddyfile" --adapter caddyfile
curl.exe "https://192.0.2.1/updates/update.php?package=host&version=2.7.0&os=windows&arch=x86_64"
```

Ответ пока `<no-update/>`, загрузка MSI по прямой ссылке должна работать.
PHP и база данных не нужны: Caddy разбирает параметры запроса и выдаёт XML.
Раздача реализована средствами `handle_path` и `query` Caddy 2.10.2:
https://caddyserver.com/docs/caddyfile/directives/handle_path
https://caddyserver.com/docs/caddyfile/matchers#query

На одном тестовом Host проверьте HTTPS **самой Aspia**, а не только браузером:
сертификату должен доверять и её механизм загрузки. Не отключайте проверку TLS.
Сохраните адрес в настройках прежде, чем нажимать «Проверить обновления».

## Настроить компьютеры батником

Два файла из папки `host` держите рядом. Закройте окно настроек Aspia, затем
правой кнопкой по `Configure-Updates.bat` → **Запуск от имени администратора**.
Требуется Windows PowerShell 5.1 или новее. Скрипт записывает только:

```json
"AutoUpdateEnabled": "true",
"UpdateCheckFrequency": "1",
"UpdateServer": "https://192.0.2.1/updates"
```

Все значения остаются строками. LastUpdateCheck не сбрасывается, немедленная
проверка не вызывается. JSON сначала проверяется, затем атомарно заменяется;
рядом создаётся `host.json.before-updates-<идентификатор>.bak` с исходными данными.
Сохраняются права доступа. Если исходник менялся параллельно, операция прерывается
до замены. Не редактируйте настройки из GUI одновременно со скриптом.
Служба отслеживает файл и перечитывает настройки; скрипт её не останавливает.
При необходимости отката закройте настройки, верните резервную копию на место
host.json и проверьте настройки в интерфейсе.

Router не распространяет эти настройки: запуск нужен на каждом Host, вручную
или средствами администрирования Windows. Программа не требует вводить их только через GUI.

## Включить выдачу после пробного обновления

Пока настроен **только один тестовый Host 2.7.0**, замените соответствующий
`host-x86.xml` / `host-x86_64.xml` содержимым одноимённого `.xml.example`.
Это включает выдачу 2.7.1 сразу всем настроенным Host данной разрядности.
Для проверки встроенного автообновления нужен ещё не обновлённый Host 2.7.0;
либо ждите, пока наступит срок проверки, либо используйте ручную кнопку.
Батник намеренно не меняет LastUpdateCheck.

После проверки установки через сервер и восстановления соединения можно запускать
батник на остальных компьютерах. Заранее выберите удобное окно обслуживания:
встроенный механизм не умеет откладывать установку до завершения сеанса.
Чтобы прекратить новые предложения обновления, верните XML с `<no-update/>`.
Это не отменяет уже начатую загрузку или установку.

Фрагмент выдаёт 2.7.1 только Host **2.7.0 для Windows** и выбирает разрядность
по самому приложению, а не по Windows. Прочим приложениям/версиям отвечает
«нет обновлений». Для будущих выпусков меняются MSI, XML и фильтр версии.
Сервер обновлений — доверенный источник исполняемого кода; доступ на запись
к его файлам должен оставаться только у администратора. Каталог публичный,
отсутствие ссылки в меню не делает файлы приватными.

## Проверено при подготовке

- Caddy 2.10.2: проверка конфигурации и 9 локальных HTTP-проверок маршрутизации,
  выбора x86/x64, отсутствия предложения для других версий/пакетов,
  скачивания файла и отсутствия листинга каталога.
- PowerShell 7.4.6: синтаксический разбор и 4 проверки преобразования JSON
  (полная конфигурация, пустая, без параметров обновления и уже настроенная);
  проверено сохранение остальных полей.
- BAT/PowerShell: живой Windows Host и его ACL/наблюдатель файлов в этой среде
  недоступны; первое применение проводится на тестовом компьютере.
- Никаких изменений рабочего Caddy, конфигураций Host или публикации обновления
  этим коммитом не выполнялось. Повторная сборка MSI для этих файлов не требуется.
