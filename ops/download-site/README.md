# Страница загрузок Aspia+

`ci/finalize-preview.ps1` создаёт ZIP после успешных сборок x86 и x64. Внутри
сохраняется одна корневая папка `aspia-downloads`: `site/` с готовой страницей,
восемью MSI, исходниками, контрольными суммами и описанием выпуска, этот файл
и `Caddy-downloads.fragment`. Для чтения страницы серверное приложение не нужно.

## Размещение на существующем сайте

1. Проверьте весь workflow и контрольную сумму ZIP из `SHA256SUMS.txt` выпуска.
2. Распакуйте его отдельно. Скопируйте содержимое `aspia-downloads/site/` в
   `C:\Web\Aspia\downloads`. Существующие другие каталоги сайта сохраняются.
3. Добавьте фрагмент Caddy внутрь существующего HTTPS-блока сайта. Он обслуживает
   только `/aspia/`; TLS, другие страницы и маршруты не меняются.
4. Проверьте конфигурацию через `caddy validate --config <путь-к-Caddyfile>` и
   примените штатным для вашего сервера способом. Откройте `/aspia/`, скачайте
   один пакет и сравните SHA-256 с `site/SHA256SUMS.txt`.

В этом комплекте нет адреса рабочего сервера, учётных данных и команд удалённого
развёртывания. GitHub draft приватен: поэтому страница ссылается на копии файлов
в `site/files/`, а не на требующие авторизации ссылки GitHub. Размещение этой
папки открывает её загрузки аудитории существующего сайта; выставлять на сайт
пакеты следует после проверки пилотного сеанса.

## Обновление программ

Назначение пакетов и порядок пилотной проверки описаны в `site/files/README-preview.md`.
Это предварительный выпуск. Router требуется для центрального журнала, Host —
для отправки его событий, Console — для просмотра и отчётов. Relay 2.7 остаётся.
Перед обновлением Router сохраняют его конфигурацию, базу и ключи при остановленной
службе; для Host выбирают разрядность установленного Host. Удалять старую версию
перед запуском MSI не требуется.

Комплект не меняет `/updates/update.php`, XML feeds и настройки автоматического
обновления. Сохранённый проектный каталог `ops/update-server` к публикации этой
страницы не относится.
