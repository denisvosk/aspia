# Aspia 2.7.1: экспериментальный файловый буфер Windows

Это частная доработка Aspia 2.7.0 (исходный тег 488a77e13dc0c0ee07e4a6838e6ae400ae0c1c7f), а не официальный релиз автора Aspia. Лицензия GPLv3 или более поздняя сохранена. Новые файлы и изменения помечены как community continuation (2026).

## Что изменено

Host, Client и Console поддерживают копирование файлов и папок через буфер Windows: Ctrl+C в Проводнике на одной машине, Ctrl+V в Проводнике или на рабочем столе другой. Обе стороны должны использовать эту сборку. В настройках сеанса должен быть включён буфер обмена; учётная запись Host должна иметь права управления рабочим столом и передачи файлов. В режиме просмотра файловый буфер недоступен.

Используются существующий зашифрованный транспорт 2.7, ClipboardEvent и FilePacketizer. Поддержка согласовывается отдельным флагом. Исходные номера полей протокола, Router и Relay не менялись. Старые компоненты 2.7 продолжают использовать прежний текстовый буфер и отдельное окно передачи файлов.

Файлы читаются по запросу вставки, блоками до 256 КиБ. Передаются только элементы текущей скопированной подборки. Запрос не может содержать произвольный путь на исходном компьютере. Внутренний идентификатор получателя назначает служба Host из аутентифицированного сеанса. Ограничены размеры сообщений, количество файлов и одновременных потоков. Разрыв сеанса или смена подборки прекращает незавершённые потоки. Исправлено время жизни отложенных уведомлений ClipboardMonitor при закрытии сеанса. Служба Host теперь учитывает настройку отключения автоматического обновления: в исходной 2.7 её обработчики не проверяли этот флаг.

## Ограничения предварительной сборки

- Windows, x86. Приложения x86 работают и на 64-разрядной Windows. Это не пакет обновления для установленного x64 Host: тестировать обновление следует на той же архитектуре.
- Поддерживается копирование, не перемещение: Ctrl+X не удаляет исходник на удалённой машине.
- До 4096 элементов в одной подборке. Относительное имя должно помещаться в FILEDESCRIPTOR Windows; для первого варианта ограничено также 259 байтами UTF-8. Ссылки и junction не обходятся. Недопустимая подборка не передаётся; используйте обычную передачу файлов.
- Переносятся содержимое и структура папок. ACL, альтернативные потоки NTFS и временные метки не переносятся.
- Ожидание следующего блока ограничено 30 секундами. После отмены/ошибки повторите Ctrl+C. Медленный канал делят изображение рабочего стола и файлы; отдельного ускоренного канала пока нет.
- Буфер Windows общий для сеансов одного пользователя. Несколько окон удалённого доступа могут менять текущую подборку, как и обычные приложения Windows.
- При незавершённой вставке Windows может оставить частичный файл в папке назначения. Ошибка возвращается Проводнику; такой файл нужно удалить или заменить повторной вставкой.
- MSI не подписаны сертификатом автора. Это тестовая сборка. Все повторные preview имеют ProductVersion 2.7.1: перед другой preview удалите предыдущую тестовую сборку.

## Проверка перед использованием

Не обновляйте сразу рабочие Host. Используйте две тестовые Windows-машины и сохраните установщики 2.7.0, адресную книгу Console и конфигурацию Host (`C:\ProgramData\aspia\host.json`). Конфигурация содержит секреты: храните резервную копию приватно.

1. Установите Host на тестовую машину, Client или Console — на вторую. На тестовом Host отключите автоматическое обновление, чтобы он не заменил доработанную сборку релизом из другого источника. Проверьте подключение через существующие Router/Relay 2.7.
2. Скопируйте и вставьте файл в обе стороны. Затем проверьте несколько файлов, кириллицу, вложенные и пустые папки, файл нулевого размера, файл больше 1 ГБ. Сравните SHA256 исходника и результата.
3. Проверьте отмену вставки, разрыв связи, закрытие окна, новую подборку во время вставки, блокировку/разблокировку Windows и повторное подключение.
4. Отключите буфер обмена; убедитесь, что файловый буфер перестал работать. Проверьте пользователя без права передачи файлов, режим просмотра и два одновременных клиента.
5. Проверьте новый Client с исходным Host 2.7.0 и исходный Client с новым Host: рабочий стол, текст и прежняя передача файлов должны работать.
6. На отдельной тестовой машине проверьте обновление x86 Host 2.7.0 → 2.7.1: служба запускается, ID, Router, учётные записи и настройки сохранились. Не кладите рядом с MSI файл `aspia-host-config.json`: штатный установщик импортирует его.

Автотесты протокола и OLE запускаются в GitHub Actions. Извлечение MSI сверяет упакованные EXE/DLL с результатом сборки. Эти проверки не заменяют интерактивную проверку двух машин и реального обновления установленного Host. Пока она не завершена, релиз остаётся черновиком и не размещается на сервере автообновлений.

## Сборка и исходники

Сборка описана в `.github/workflows/clipboard-windows.yml`: MSVC v142, CMake 3.28.4, WiX 3, vcpkg4aspia 7eb700c9688daed6d8bdcdc571ebe3eedea6a774, статические зависимости x86 Release. Для удалённых пакетов инструментов MSYS2 сохранён обновлённый каталог URL/SHA512 из microsoft/vcpkg@2200159cd465157f20133e363e4604ac4d68181b; версии библиотек Aspia не обновляются. Workflow собирает и проверяет исходники, создаёт три MSI с оригинальными UpgradeCode и языковыми ресурсами, затем сохраняет исходники и SHA256 в приватный черновик релиза. Запуск: изменение `ci/build-request.txt` в PR либо workflow_dispatch, когда workflow доступен в основной ветке.

При передаче изменённых MSI другим людям предоставляйте соответствующие исходники этой же сборки, LICENSE.md и сведения об изменениях. Исходники включены в тот же релиз. Перед дальнейшим распространением отдельно учтите лицензии статически включённых библиотек.
