# Aspia+ 2.7.2: журнал сеансов и автоматический учёт техники

Предварительный выпуск ветки Aspia 2.7. Перед использованием на рабочем парке нужен пилот на двух компьютерах. Программа не развёртывает обновления автоматически.

## Состав выпуска

Установщики Console, Client, Host и Router для Windows x86 и x64; соответствующие исходники, лицензия, контрольные суммы и комплект статической страницы загрузок. Relay остаётся версии 2.7.

Новые функции требуют согласованного обновления компонентов:

1. Обновить административную Console и используемые сотрудниками Client/Console.
2. Сохранить конфигурацию, базу и ключи Router. Обновить Router с сохранением этих файлов.
3. Обновить один пилотный Host и проверить журнал, инвентаризацию, обычное подключение и существующий буфер обмена. Затем расширять пилот.

Новая Console подключается к прежним Host/Router 2.7. Старые Host и Relay могут работать с новым Router через прежний транспорт. Однако старые Client/Console содержат проверку, отклоняющую более новую версию Host/Router: **сначала обновляйте программы, с которых выполняют подключения**. Смена протокола на Aspia 3.x и настройка новых портов не требуются.

Для Host выбирать архитектуру уже установленного Host, а не только архитектуру Windows. Предварительное удаление Host не требуется. Не класть рядом с MSI `aspia-host-config.json`, если не планируется импорт новой конфигурации. Обновление службы прерывает текущий сеанс удалённого доступа.

## Журнал сеансов

Открыть **Управление маршрутизатором → Журнал сеансов** под административной учётной записью Router.

Host сообщает о сеансе после успешной проверки своей учётной записи и необходимого локального подтверждения. Журнал хранится на Router независимо от открытой Console. В записи присутствуют:

- персональный логин **Router**, связанный сервером с фактически начавшимся сеансом;
- отдельный подтверждённый логин **Host**, с которым выполнен вход на компьютер;
- Host ID и исходное имя удалённого компьютера;
- имя из открытой адресной книги, сопоставленное по Host ID в области выбранного Router;
- тип сеанса, начало, окончание, продолжительность и состояние;
- имя компьютера клиента, сообщённое клиентом;
- адрес клиента, наблюдаемый Router, адрес транспортного соединения и адрес Host;
- время последнего подтверждения серверу.

Если сотрудники пользуются персональными логинами Router, а реквизиты доступа к Host общие, журнал позволяет различать их по логину Router. Сервер сохраняет свою подтверждённую учётную запись и связывает её с конкретным предложением соединения. Host возвращает идентификатор этого соединения только после успешной авторизации и необходимого подтверждения. Одно предложение не может подтвердить разные сеансы или другой Host. Имена Router не принимаются на доверии из сообщения клиента или Host.

Для прямых соединений, старых компонентов и сеансов без серверной записи связи логин Router показывается как «Не подтверждён»; логин Host остаётся отдельным полем. Общий логин Router сам по себе не позволяет различать отдельных сотрудников. Для персональной атрибуции через маршрутизатор следует использовать уже заведённые персональные учётные записи Router.

Группировка: «Сегодня», «Вчера», «На этой неделе», «На прошлой неделе», «Ранее», внутри — календарные даты. Часовой пояс соответствует компьютеру с Console. Есть фильтры по периоду, точному логину Router или Host и Host ID, поиск по загруженным строкам и выгрузка CSV. В CSV даты явно обозначены как UTC.

Страницы ограничены 500 записями. За один просмотр загружается до 10 000 строк; для более длинной истории следует сузить период. Счётчики и CSV явно относятся к загруженным и видимым строкам. По умолчанию открывается последний месяц.

Продолжительность измеряется монотонными часами Host. Для активного сеанса и окончания, которое не удалось подтвердить, показана нижняя граница известной продолжительности. При потере Host/Router запись не превращается в вымышленное точное время выхода. После восстановления связи более новое подтверждение может уточнить состояние.

Host хранит очередь отправки на диске и удаляет завершённое событие после подтверждения сохранения Router. Копия активного события остаётся до завершения; после аварийного перезапуска можно сообщить о неподтверждённом окончании. Очередь привязана к адресу, порту и ключу Router. Прямой сеанс также можно зарегистрировать, если Host уже имеет ID этого Router; для Host, никогда не регистрировавшегося на Router, центрального журнала нет.

Данные начинают накапливаться после установки. Прежние подключения восстановить задним числом невозможно. Это административный журнал событий, а не видеозапись действий и не доказательство личности владельца общей учётной записи. При подключении через Relay транспортный адрес может принадлежать Relay.

## Автоматический отчёт по всей адресной книге

Новый Host собирает компактную аппаратную сводку при регистрации и затем раз в сутки. Повторная отправка ранее собранного снимка не должна менять его возраст. Сбор не требует открытой Console или активного удалённого рабочего стола. Сложные обращения к оборудованию изолированы в отдельном процессе с ограничением времени; неудача не должна удалять последний успешный снимок.

Router отдельно накапливает присутствие Host и последнюю аппаратную сводку. Присутствие отслеживается и для прежних зарегистрированных Host, аппаратная сводка автоматически передаётся обновлёнными Host.

Открыть **Отчёт по оборудованию** в Console. Отчёт включает всю открытую адресную книгу с вложенными группами; обходить карточки компьютеров не требуется. Console объединяет сохранённые сервером сведения с названиями рабочих мест и групп в книге.

Отчёт можно сохранить как оформленный HTML со сводкой по группам и техническим приложением, открыть в браузере и распечатать, в том числе в PDF. Подробная таблица выгружается в CSV с кодировкой UTF-8 для Excel. Если включён поиск, выгрузка относится к выбранным строкам, и в HTML явно указан действующий фильтр.

В сводке для руководителя показаны охват сбора, активность по группам и конкретные основания для технической проверки. В приложении — строки рабочих мест и основные характеристики:

- модель CPU, физические ядра, логические процессоры и сообщённая частота;
- установленная RAM; если доступна только память, видимая ОС, это отмечено отдельно;
- физические накопители: модель, объём и тип SSD/HDD/не определён;
- логические тома: общий и свободный объём, файловая система;
- ОС и архитектура, материнская плата;
- последнее наблюдение в сети, дата сбора и первоначального получения аппаратного снимка сервером.

Тип накопителя определяется по сведениям Windows и драйвера, а не по маркетинговому названию. USB-мосты, RAID и виртуальные устройства могут скрывать тип: в таком случае выводится «Не определён». Объёмы физических дисков и логических томов показаны раздельно и не суммируются как разные устройства.

Порог давности и критерии проверки выбираются в отчёте. «Давно не появлялся» означает необходимость проверки, а не автоматическое списание. Отпуск, неисправность и замена рабочего места не выводятся из отсутствия соединения как установленный факт. Дата BIOS не используется как дата покупки компьютера.

Количество записей книги и уникальных конечных точек показывается раздельно. Несколько карточек могут указывать на один Host ID; несколько Host ID на терминальном сервере могут относиться к одному физическому компьютеру. Поэтому число Host ID не выдаётся за бухгалтерский учёт физических единиц. Старые и новые записи рабочих мест требуют административного решения о выводе из эксплуатации.

Публичные исходники и тесты не содержат адресных книг, исторических таблиц, фамилий, конфигураций или баз пользователей. Автоматический аппаратный снимок не содержит паролей и ключа активации Windows.

## Хранение и восстановление

Рядом с существующей базой Router создаются отдельные файлы:

- `router-audit.db3`: журнал сеансов и наблюдения присутствия;
- `router-inventory.db3`: последние аппаратные снимки.

У Host создаётся отдельная очередь `host-audit-<идентификатор Router>.db3`. Существующие базы авторизации, пользователи и ключи не мигрируются в новый формат. Чтение централизованных журналов и инвентаризации разрешено через административный сеанс Router.

SQLite использует WAL. Для файловой резервной копии следует остановить соответствующую службу и копировать согласованный комплект базы и её файлов, либо использовать SQLite backup API. Простое копирование одного файла активной WAL-базы может потерять недавние записи. В первой предварительной версии автоматического удаления истории нет: рост журнала нужно учитывать при резервном копировании и выделении места. При ошибке открытия хранилища соответствующая возможность не объявляется доступной.

## Проверки выпуска

CI выполняет независимые проверки хранилищ, повторной доставки, страниц, идентичности и давности снимков; проверяет привязку персонального логина Router к сеансу, отклонение подмены и повторного использования связи; проверяет группировку дат, CSV и отчётные данные; компилирует новый интерфейс и запускает прежние протокольные и Windows/OLE тесты. Windows-пакеты проходят извлечение и сравнение бинарников, обновление Host и сохранение конфигурации/пользователей/Host ID при обновлении Router. Дополнительно запускается сборщик оборудования из установленного нового Host: проверяются ограничения времени/размера, корректность бинарной сводки и получение CPU, RAM и сведений об ОС на настоящей Windows-среде CI.

Наличие файлов одного архитектурного задания не означает завершённый выпуск. Полный комплект формируется завершающим заданием после успешных проверок обеих архитектур. Каждый пакет идентифицируется версией, исходным commit и SHA-256.

Живые проверки на пилоте остаются необходимыми: персональные входы в обе стороны, длительный сеанс и обрыв связи, перезапуск Host/Router, получение отчёта при закрытой Console, SSD/HDD/неопределённый тип, корректные группы книги и экспорт. Базовые рабочие возможности, включая существующий обмен файлами и изображениями через буфер, следует проверить на том же пилоте.

## Размещение установщиков на сайте

После полного CI создаётся архив `aspia-downloads-<release>.zip` с постоянной корневой папкой `aspia-downloads`. В нём статическая страница с локальными ссылками на MSI и исходники, manifest, SHA-256 и пример фрагмента Caddy. Развёртывание этого комплекта не включает автоматическое обновление Host. Живой сайт изменяется только отдельной операцией на сервере; успешная сборка архива не означает его развёртывания.

## Android

У upstream есть официальный Android-клиент, однако начиная с 3.1.2 прекращена поддержка 2.x. Даже прежний Android 3.0.37 использует новый Router-путь и не является готовой заменой для Router 2.7. В этот Windows-выпуск совместимый APK не включён. Для телефона нужно отдельно переносить совместимый сетевой путь либо завершать мобильный интерфейс собственного веб-шлюза.

Первичные источники исследования: [changelog Aspia](https://aspia.org/changelog), [документация Client и Android](https://aspia.org/docs/client.html), [Router](https://aspia.org/docs/router.html), [upstream 3.4.3](https://github.com/dchapyshev/aspia/releases/tag/v3.4.3). Предлагаемые подключения в upstream Access Log сами по себе не заменяют подтверждённые Host события начала и окончания.
